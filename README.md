# คลังความรู้แมวอักษร (Aksorn Cat Knowledge Hub)

เว็บไซต์ static (HTML/CSS/JS) ที่ดึงข้อมูลจาก Google Sheet ทีมจึงเพิ่ม แก้ไข และจัดหมวดเนื้อหาได้โดยไม่ต้องแก้โค้ด Google Sheet จึงทำหน้าที่เป็น **ระบบจัดการเนื้อหา (CMS)** ของคลัง

## ไฟล์ในโฟลเดอร์

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `index.html`, `landing.css`, `landing.js` | หน้าแรก: ฉากสามมิติลานคณะยามค่ำ เล่าเรื่องโครงการเป็น 4 บท และดึงตัวเลขสดจากชีต (ไม่ต้องแก้) |
| `cats.html`, `style.css`, `app.js` | ตัวคลัง: แมวในคณะ ประวัติรายตัวและประวัติการดูแล คลังความรู้แยกหมวด ค้นหารวม แบ่งปันความรู้ ผังครอบครัว QR (ไม่ต้องแก้) |
| `data.js` | ตัวอ่านข้อมูลที่ทั้งสองหน้าใช้ร่วมกัน (ไม่ต้องแก้) |
| `config.js` | **ไฟล์เดียวที่ต้องแก้** ใส่ลิงก์ชีต ฟอร์ม เบอร์ติดต่อ เครดิต |
| `photos/` | รูปแมวจาก Instagram @aksorncats (ให้เครดิตในช่องที่มาของข้อมูลแต่ละตัว) |
| `models/` | โมเดลสามมิติอาคาร BRK MCS หอประชุม และเสาธง ที่บีบอัดแล้ว |
| `data-sample.js` | ข้อมูลตั้งต้น: แมวและประวัติที่ดึงจาก Instagram @aksorncats (รอยืนยัน) และบทความตัวอย่าง ใช้แสดงผลจนกว่าจะเชื่อมชีตจริง |
| `cats_template.csv`, `articles_template.csv`, `history_template.csv` | แม่แบบสำหรับ import เข้า Google Sheet ทีละแท็บ |

ลองเปิดดู: ดับเบิลคลิก `index.html` (ต้องต่ออินเทอร์เน็ต)

## เปิดระบบรับเรื่อง (ฟอร์มแบ่งปันความรู้) ประมาณ 5 นาที

ตอนนี้ฟอร์มยังไม่ส่งเข้าชีต (หน้าเว็บจะบอกผู้ใช้ตามจริง) วิธีเปิด:
1. เปิดชีตของทีม → ส่วนขยาย (Extensions) → Apps Script
2. วางโค้ดจาก `tools/submissions.gs` → บันทึก
3. ทำให้ใช้งานได้ (Deploy) → รายการใหม่ → ประเภท Web app · เรียกใช้ในฐานะ ฉัน · ผู้มีสิทธิ์ ทุกคน
4. คัดลอก URL ที่ลงท้ายด้วย `/exec` ไปใส่ใน `config.js` ช่อง `SUBMIT_URL` แล้ว push
ทุกเรื่องจะเข้าแท็บ `Submissions` สถานะ "รอตรวจ" ผู้ดูแลเนื้อหาตรวจแล้วค่อยนำไปใส่ข้อมูลจริง

## คอลัมน์ที่ทีมเพิ่มในชีตได้ (เว็บอ่านให้อัตโนมัติ)

- `สีขน` (หรือ Coat): ส้ม ดำ ขาวดำ ขาว สามสี ลายสลิด ครีม → ใช้กับหน้าหาแมว (ตอนนี้ใช้ค่าที่ระบุจากรูปใน `config.js` ช่อง `CAT_EXTRA`)
- `ปกติ` (หรือ Normal / Habits): ปกติแมวตัวนี้กินเวลาไหน นอนที่ไหน นิสัยอะไร → แสดงในการ์ด "ปกติแมวตัวนี้เป็นอย่างไร"
- `วิธีเข้าหา` (หรือ Approach): ถ้าไม่ใส่ เว็บใช้ข้อความจากช่อง Personality

## ข้อมูลแมวตอนนี้มาจากชีตของทีมโดยตรง

เว็บอ่านแท็บ `Cat_profile` ใน Google Sheet ของทีมแบบสด (ตั้งไว้ใน `config.js` ช่อง `SHEET_CSV_URL`) แก้ข้อมูลในชีตแล้วเว็บจะอัปเดตเองภายในไม่กี่นาที ชีตต้องแชร์แบบ "ทุกคนที่มีลิงก์ดูได้"

- ระบบหาแถวหัวตารางเอง (แถวที่มีคำว่า Name) แถวหัวข้อกลุ่มด้านบนไม่เป็นปัญหา
- อ่านคอลัมน์จากชื่อหัว ไม่ใช่ตำแหน่ง: Name, Photo, Distinguishing marks, Sex, Age, Vaccination Status, ทำหมัน, Health notes, Status, Personality, Usual locations, Relationship, Primary caretaker(s), Last seen, Note
- Status ที่เข้าใจ: active / back home (ไปกลับ) / missing / adopted / passed away ช่องว่าง = ยังไม่ระบุ
- Relationship เช่น “พี่น้องกับมีตัง” จะเชื่อมแมวสองตัวเป็นพี่น้องในผังครอบครัวให้อัตโนมัติ
- คอลัมน์ที่ไม่มีหัว (บันทึกสัมภาษณ์) จะแสดงในหน้าแมวตัวนั้นเป็น “บันทึกจากการสัมภาษณ์ผู้ดูแล”
- รูป: ใส่ลิงก์รูปในช่อง Photo หรือเพิ่มชื่อแมวกับไฟล์รูปใน `CAT_PHOTOS` ใน `config.js`
- ถ้าโหลดชีตไม่ได้ เว็บจะใช้สำเนาที่เก็บไว้ใน `data-sample.js` และขึ้นแถบแจ้งเตือน

## รูปแมว: ดึงจากโฟลเดอร์ Google Drive ในช่อง Photo

ช่อง Photo ในชีตลิงก์ไปที่โฟลเดอร์ Drive ของแมวแต่ละตัว เว็บอ่านโฟลเดอร์เองไม่ได้ (และเบราว์เซอร์ส่วนใหญ่เปิดไฟล์ HEIC จาก iPhone ไม่ได้) จึงต้องรันสคริปต์ดึงรูปมาเก็บในเว็บ

1. โฟลเดอร์ต้องแชร์แบบ "ทุกคนที่มีลิงก์ดูได้"
2. อยากเลือกรูปปก ให้ตั้งชื่อไฟล์ขึ้นต้นด้วย `cover` เช่น `cover.jpg`
3. ในโฟลเดอร์เว็บ รัน `python -I tools/sync_photos.py` (ต้องมี Pillow และ openpyxl) แล้ว commit และ push
4. สคริปต์แปลง HEIC เป็น JPEG ทำรูปเล็กสำหรับหน้ารวมและรูปใหญ่สำหรับหน้าแมว สูงสุด 8 รูปต่อตัว แล้วเขียน `photos/manifest.js`

## ขั้นที่ 1: สร้าง Google Sheet (คลังข้อมูลหลัก) (แบบแม่แบบเดิม ใช้ถ้าจะตั้งชีตใหม่)

1. สร้าง Google Sheet ใหม่ ตั้งชื่อชีตว่า `cats`
2. File → Import → Upload → เลือก `cats_template.csv` → "Replace current sheet"
3. ลบแถวแมวสมมติ แล้วกรอกแมวจริง (ห้ามเปลี่ยนชื่อหัวคอลัมน์)
4. File → Share → **Publish to web** → เลือกชีต `cats` → รูปแบบ **Comma-separated values (.csv)** → Publish
5. คัดลอกลิงก์ที่ได้ไปใส่ใน `config.js` ช่อง `SHEET_CSV_URL`

หลังแก้ชีต เว็บจะอัปเดตเองภายในไม่กี่นาที (Google ใช้เวลารีเฟรช CSV ประมาณ 5 นาที)

### ความหมายของแต่ละคอลัมน์

| คอลัมน์ | กรอกอะไร | ตัวอย่าง |
|---|---|---|
| `id` | รหัสแมว ห้ามซ้ำและห้ามเปลี่ยนภายหลัง (QR อ้างอิงรหัสนี้) | `c01` |
| `name` | ชื่อหลัก (preferred name) | แม่ส้ม |
| `nicknames` | ชื่ออื่นที่คนเรียก คั่นด้วย `,` | ส้ม, แม่ใหญ่ |
| `photo` | ลิงก์รูป: ลิงก์ Google Drive ได้ (ต้องตั้งแชร์เป็น "Anyone with the link") | |
| `sex` | `male` / `female` / `unknown` (หรือ ตัวผู้/ตัวเมีย) | female |
| `age` | อายุโดยประมาณ | ประมาณ 6 ปี |
| `marks` | ลักษณะเด่นที่ใช้แยกตัว | ส้มทั้งตัว หูซ้ายตัดปลาย |
| `sterilised` | `yes` / `no` / `unknown` | yes |
| `vaccinated` | `yes` / `no` / `unknown` | yes |
| `health_notes` | อาการ/ข้อควรระวัง | น้ำหนักเกิน งดขนม |
| `personality` | นิสัย | ขี้อาย อย่าอุ้ม |
| `locations` | จุดที่มักอยู่ คั่นด้วย `,` | โรงอาหาร, ลานหน้าคณะ |
| `mother_id` | **`id` ของแม่** (ทำให้ผังครอบครัวเชื่อมกัน) | c01 |
| `status` | `active` / `missing` / `adopted` / `passed` | active |
| `caretakers` | ผู้ดูแลหลัก (ใช้ตำแหน่งหรือชื่อเล่นที่ได้รับอนุญาต) | พี่แม่บ้านกะเช้า |
| `last_seen` | วันที่พบล่าสุด (YYYY-MM-DD) | 2026-11-05 |
| `source` | ที่มาของข้อมูล (สำคัญมากในเชิง KM) | สัมภาษณ์พี่แม่บ้าน 7 พ.ย. 69 |
| `notes` | อื่น ๆ | |

> พี่น้องไม่ต้องกรอกเอง ระบบคำนวณจากแมวที่มี `mother_id` เดียวกัน


## ขั้นที่ 1b: แท็บคลังความรู้ (articles) และประวัติการดูแล (history)

ใน Google Sheet ไฟล์เดียวกัน สร้างแท็บเพิ่มอีก 2 แท็บ ชื่อ `articles` และ `history` แล้ว import แม่แบบแต่ละไฟล์เข้าไป จากนั้น Publish to web ทีละแท็บเป็น CSV (แต่ละแท็บได้ลิงก์ของตัวเอง) แล้วใส่ใน `ARTICLES_CSV_URL` และ `HISTORY_CSV_URL`

### คอลัมน์ของ `articles`

| คอลัมน์ | กรอกอะไร |
|---|---|
| `id` | รหัสบทความ ห้ามซ้ำ เช่น `a07` |
| `title`, `summary` | ชื่อบทความ และสรุปหนึ่งถึงสองประโยค |
| `category` | `feeding` (การให้อาหาร) / `health` (สุขภาพ) / `behavior` (พฤติกรรม) / `hygiene` (สุขอนามัย) / `experience` (ประสบการณ์จากผู้ดูแล) |
| `body` | เนื้อหา: เว้นบรรทัดว่าง = ขึ้นย่อหน้าใหม่, บรรทัดที่ขึ้นต้นด้วย `## ` = หัวข้อย่อย, บรรทัดที่ขึ้นต้นด้วย `- ` = รายการ |
| `author`, `source`, `date` | ผู้เขียน ที่มาของความรู้ (เช่น สัมภาษณ์ใคร เมื่อไร) วันที่ (YYYY-MM-DD) |
| `tags` | คำสำคัญสำหรับค้นหา คั่นด้วย `,` |
| `related_cats` | `id` ของแมวที่เกี่ยวข้อง คั่นด้วย `,` (บทความจะไปแสดงในหน้าแมวตัวนั้นด้วย) |
| `reviewed_by` | ผู้ตรวจทาน (ว่าง = เว็บแสดงว่า "ยังไม่ได้ตรวจทาน") |
| `status` | ว่าง หรือ `published` = แสดงบนเว็บ, `draft` / `pending` = ซ่อนไว้รอตรวจ |

### คอลัมน์ของ `history`

| คอลัมน์ | กรอกอะไร |
|---|---|
| `date` | วันที่ (YYYY-MM-DD) |
| `cat_id` | `id` ของแมว |
| `type` | `health` / `sterilised` / `vaccine` / `feeding` / `sighting` / `birth` / `adopted` / `other` |
| `note`, `by` | บันทึก และผู้บันทึก |
| `status` | เหมือน articles: `draft` / `pending` = ยังไม่แสดง |

### ขั้นตอนตรวจทานก่อนเผยแพร่ (moderation)

ข้อมูลที่คนทั่วไปส่งผ่านฟอร์มจะไปลงชีตคำตอบแยก ทีมคัดลอกแถวที่ผ่านการตรวจมาใส่แท็บ `articles` หรือ `history` ถ้ายังไม่แน่ใจให้ใส่ `status` เป็น `pending` ไว้ก่อน เว็บจะยังไม่แสดงจนกว่าจะเปลี่ยนเป็น `published` ขั้นนี้คือการตรวจสอบและคัดกรองความรู้ (validation) ในกระบวนการจัดการความรู้

## ขั้นที่ 2: สร้าง Google Form (ช่องทางแจ้งข่าวและแบ่งปันความรู้)

1. สร้าง Google Form ตัวอย่างคำถาม: ชื่อแมว / เรื่องที่แจ้ง (เห็นแมว, แมวป่วย, แมวตัวใหม่, ข้อมูลผิด) / รายละเอียด / สถานที่ / รูป / ชื่อผู้แจ้ง (ไม่บังคับ)
2. ให้คำตอบไปลง **ชีตแยก** ไม่ใช่ชีต `cats` เพื่อให้ทีมตรวจสอบก่อนแก้คลัง (นี่คือขั้น validation/curation ในกระบวนการ KM ใช้อธิบายในรายงานได้)
3. คัดลอกลิงก์ฟอร์ม (ลงท้าย `/viewform`) ใส่ใน `FORM_URL`
4. สร้างฟอร์มที่สอง "แบ่งปันความรู้" สำหรับส่งบทความ เคล็ดลับ หรือประสบการณ์ (คำถาม: หัวข้อ / หมวด / เนื้อหา / แมวที่เกี่ยวข้อง / ชื่อที่อยากให้ใส่เป็นเครดิต / อนุญาตให้เผยแพร่หรือไม่) แล้วใส่ลิงก์ใน `SHARE_FORM_URL`
5. (ไม่บังคับ) ให้ฟอร์มกรอกชื่อแมวอัตโนมัติ: เมนู ⋮ → Get pre-filled link → พิมพ์อะไรก็ได้ในช่องชื่อแมว → Get link → หาเลข `entry.xxxxxxx` ในลิงก์ → ใส่ใน `FORM_CAT_ENTRY`

## ขั้นที่ 3: เว็บจริงบน GitHub Pages

เว็บขึ้นแล้วที่ **https://pheechan.github.io/aksorn-cat-hub/** (repo: https://github.com/pheechan/aksorn-cat-hub) ทุกครั้งที่ push ขึ้น branch `main` เว็บจะอัปเดตเองภายใน 1–2 นาที ถ้าจะตั้งเองใหม่ทำตามนี้:

1. สมัคร/ล็อกอิน github.com → New repository → ตั้งชื่อ เช่น `arts-cats` → Public → Create
2. "uploading an existing file" → ลากไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้นไป → Commit
3. Settings → Pages → Source: "Deploy from a branch" → Branch `main` / `(root)` → Save
4. รอ 1–2 นาที จะได้ลิงก์ `https://<username>.github.io/arts-cats/`
5. ใส่ลิงก์นี้ใน `config.js` ช่อง `SITE_URL` แล้วอัปโหลด `config.js` ใหม่

## ขั้นที่ 4: พิมพ์ QR

เปิด `cats.html#/qr` (ลิงก์อยู่ท้ายหน้า "เกี่ยวกับโครงการ") → กดพิมพ์ QR จะพาไปที่ `cats.html#/cat/<id>` ทำหลังตั้ง `SITE_URL` แล้วเท่านั้น และขออนุญาตคณะก่อนติด

## ก่อนเผยแพร่จริง เช็กให้ครบ

- [ ] ข้อมูลติดต่อฉุกเฉินใน `config.js` ตรวจแล้วว่าถูกต้อง (เบอร์ รพ.สัตว์ เวลาทำการ)
- [ ] ได้รับอนุญาตจากพี่แม่บ้าน/ภารโรงก่อนใส่ชื่อหรือคลิปเสียง
- [ ] ไม่มีเบอร์โทรส่วนตัวในชีต
- [ ] ไม่ระบุตำแหน่งลูกแมวแรกเกิดละเอียดเกินไป
- [ ] ลบแมวสมมติออกจากชีตแล้ว (แถบเตือน "ข้อมูลตัวอย่าง" จะหายไปเอง)
- [ ] บทความตัวอย่างถูกแทนที่หรือตรวจทานโดยผู้ดูแลหรือสัตวแพทย์แล้ว (กรอก `reviewed_by`)
- [ ] บทความ a06 เป็นเรื่องสมมติ ต้องแทนด้วยบทสัมภาษณ์จริงหรือลบออก

## ส่วนต่าง ๆ ของเว็บกับกระบวนการจัดการความรู้

| ส่วนของเว็บ | ขั้นของ KM |
|---|---|
| ข้อมูลจากการสัมภาษณ์ในคอลัมน์ `source` | แสวงหา/สร้างความรู้ (SECI: externalization) |
| Google Sheet + metadata schema + ชื่อหลัก/ชื่ออื่น | จัดเก็บและจัดระเบียบ (authority control) |
| คลังความรู้แยกหมวด + ประวัติการดูแล | จัดเก็บความรู้ทั้งข้อเท็จจริงและประสบการณ์ |
| ค้นหารวมแมวและบทความ, QR ณ จุดที่แมวอยู่, ผังครอบครัว | การเข้าถึง |
| หน้าแบ่งปันความรู้ + ฟอร์ม + คอลัมน์ `status` ตรวจทานก่อนเผยแพร่ | แลกเปลี่ยน ตรวจสอบ และนำไปใช้ |
